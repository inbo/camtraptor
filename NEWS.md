# camtraptor 1.0

This is a major release that updates the internal data model to Camtrap DP 1.0, drops support for Camtrap DP 0.1.6 and introduces new functions to implement a more streamlined workflow.

## New workflow

We propose an easier workflow to explore Camtrap DPs. The main steps are:

- Read a Camtrap DP using `read_camtrapdp()`, which reexports the functionality from `camtrapdp::read_camtrapdp()`. This function supports Camtrap DP 1.0 or higher.
- Filter the data package using `filter_deployments()`, `filter_observations()` and `filter_media()`, which reexport the functionalities from `{camtrapdp}`. This allows to subset the data package based on deployment, observation and media fields. These functions are more flexible than the previous filter predicates and are much easier to use as you just write the normal operators such as `==`, `!=`, `>` or `<`, instead of `pred()`, `pred_notin()`, `pred_gt()` or `pred_lt`. Also, the filter predicates could subset the data package only based on deployment fields! To subset a data package based on observations fields you needed to use arguments such as `life_stage` or `sex` in the `get_*()` functions: not the most logical solution as filtering occurred at two different levels! So, do you want to filter? Use `filter_*()` functions: easy and consistent with the tidyverse style of data manipulation.
- Generate summary tables using `summarize_deployments()` and `summarize_observations()`, which calculate several features related to deployments and observations, respectively. These functions allow to group by one or more deployment and observation fields and to calculate the features at different temporal levels (daily, weekly, monthly or yearly).
- Visualize the summary tables using `map_summary()`, which creates a leaflet map for the desired feature. This function replaces `map_dep()`. The main advantage is that `map_summary()` starts from a grouped data frame generated by `summarize_deployments()` or `summarize_observations()`, while `map_dep()` starts from a Camtrap DP object. This means that you can easily visualize any feature generated by the summary functions, while with `map_dep()` you had to specify all filtering based on observations fields again in arguments such as `life_stage` or `sex`.

And yes, you can pipe all these steps together! A few examples are worth a thousand words:

Do you want to filter the data package to include only deployments with latitude > 51.0, longitude > 5.0 and observations of adult individuals only, then calculate the sum of individual counts and visualize it on a map? You can do it like this:

```r
library(camtraptor)
file <- "https://raw.githubusercontent.com/tdwg/camtrap-dp/1.0.2/example/datapackage.json"
x <- read_camtrapdp(file)
x %>%
  filter_deployments(latitude > 51.0, longitude > 5.0) %>%
  filter_observations(lifeStage == "adult") %>%
  summarize_observations() %>%
  map_summary(feature = "sum_count")
```

Notice that in this way you can stop at any step of the workflow and inspect the intermediate results, which is not possible with version camtraptor 0.28 or earlier. For example, you can inspect the summary tables generated by `summarize_deployments()` and `summarize_observations()` before visualizing them on a map:


Another example: do you want to calculate the duration effort at monthly level for each deployment in 2020? You can do it like this:

```r
x %>%
  filter_deployments(
    lubridate::year(deploymentStart) == 2020,
    lubridate::year(deploymentEnd) == 2020
  ) %>%
  summarize_deployments(group_time_by = "month")
# A tibble: 6 × 5
# Groups:   deploymentID, latitude, longitude, month [6]
  deploymentID latitude longitude month               effort_duration       
  <chr>           <dbl>     <dbl> <dttm>              <Duration>

3 00a2c20d         51.5      4.77 2020-07-01 00:00:00 34901s (~9.69 hours)
```

Do you want to visualize the monthly effort on a map? Just add `map_summary()` to the previous code mentioning the feature to visualize:

```r
x %>%
  filter_deployments(
    lubridate::year(deploymentStart) == 2020,
    lubridate::year(deploymentEnd) == 2020
  ) %>%
  summarize_deployments(group_time_by = "month") %>%
  map_summary(feature = "effort_duration")
```

The benefit of having just two functions to generate summary tables is that they can be easily extended in the future to include more features, grouping variables and temporal levels. Before, you needed to run many `get_*()` functions, such as `get_n_obs()`, `get_n_individuals()` or `get_rai()`, and then joining the results if you wanted an overview of all features. Also, the new workflow is more consistent with the tidyverse style of data manipulation and visualization, which makes it easier to learn for users familiar with this style.

### New functions

- New `summarize_deployments()` calculates the duration effort (#366). It is possible to group by one or more deployment fields: `deploymentID`, `locationID`, `locationName` and `deploymentTags`. The duration effort can be calculated at daily, weekly, monthly or yearly level.
- New `summarize_observations()` calculates several observations related features, such as the number of taxa, the number of events, the number of observations, the sum of individual counts and the Relative Abundance Index  (RAI) (#367). It is possible to group by one or more deployment and observation fields: `deploymentID`, `locationID`, `locationName`, `deploymentTags`, `scientificName`, `lifeStage`, `sex`, `behavior`. The features can be calculated at daily, weekly, monthly or yearly level.
- New `map_summary()` creates a leaflet map showing the desired feature, one among the ones generated by `summarize_deployments()` and `summarize_observations()`. It replaces `map_dep()` (#231, #91). The main difference is that `map_summary()` starts from a grouped data frame generated by `summarize_deployments()` or `summarize_observations()`, while `map_dep()` starts from a Camtrap DP object. 
- New `filter_out_timelapse()` allows to filter out timelapse observations (#306).

### New exported functionalities from `{camtrapdp}`

- `example_dataset()` allows to create an example dataset in Camtrap DP 1.0 format. It reexports the functionality from `camtrapdp::example_dataset`. The internal dataset `mica` is not present anymore. Raw data files in `inst/extdata` are also removed.
- `filter_deployments()`, `filter_observations()` and `filter_media()` allow to filter at data package level (#315). They reexport the functionalities from `{camtrapdp}`. See `camtrapdp::filter_deployments()`, `camtrapdp::filter_observations()` and `camtrapdp::filter_media()`.
- `deployments()`, `observations()` and `media()` allow to extract the respective tables (#317). They reexports the functionality from `{camtrapdp}`, e.g. see `camtrapdp::deployments()`.
- `deployments<-`, `observations<-` and `media<-` allow to set the respective tables (#328). They reexports the functionality from `{camtrapdp}`, e.g. see `camtrapdp::deployments<-`.
- `events()` and `taxa()` allow to extract information about events and taxa from the observations (#317). They reexport the functionalities from `{camtrapdp}`, see `camtrapdp::events()` and `camtrapdp::taxa()`.
- `locations()` allows to extract information about locations from the deployments (#317). It reexports the functionality from `{camtrapdp}`, see `camtrapdp::locations()`.
- `individuals()` allows to extract the (unique) individuals from the observations. It reexports the functionality from `{camtrapdp}`, see `camtrapdp::individuals()`.
- `contributors()` allows to extract the contributors from the `x$contributors` property. `contributors<-` is the assignment equivalent. Both reexport functionalies from `{camtrapdp}`, see `camtrapdp::contributors()` and `camtrapdp::contributors<-` respectively.

### Deprecated functions

- `read_camtrap_dp()` (with underscore) -> use `read_camtrapdp()` instead, which reexports the read functionality from `camtrapdp::read_camtrapdp` (#298).
- `get_record_table()` -> use `camtrapR_recordTable()` instead (#240).
- `get_cam_op()` -> use `camtrapR_cameraOperation()` instead (#239).
- `get_detection_history()` -> use `camtrapR_detectionHistory()` instead (#365).
- `get_species()` -> use `taxa()` instead (#343).
- `get_n_species()` -> use `summarize_observations()` instead (#243).
- `get_n_obs()` -> use `summarize_observations()` instead (#367).
- `get_n_individuals()` -> use `summarize_observations()` instead (#367).
- `get_rai()` -> use `summarize_observations()` instead (#243).
- `get_rai_individuals()` -> use `summarize_observations()` instead (#243).
- `get_custom_effort()` -> use `summarize_deployments()` instead (#366).
- `get_effort()` -> use `summarize_deployments()` instead (#366).
- `map_dep()` -> use `map_summary()` instead (#231, #91).
- `calc_animal_pos()` -> use `calculate_individual_radius_angle()` instead (#242).
- Arguments `sex` and `life_stage` are now deprecated in (deprecated) `map_dep()`. Use `filter_observations()` beforehand.

### Defunct functions

- `get_scientific_name()` and `check_species()` are now defunct. Use `taxa()` for an overview of all species (#235).
- `read_wi()` is now defunct as not in scope (#351). 
- Filter predicates (`apply_filter_predicate()`, `pred()` `pred_not()` `pred_gt()`, `pred_and()`, `pred_or()`, etc.) are now defunct. Use `filter_deployments()` (#316).
- The deprecated argument `datapkg` in `read_camtrap_dp()` is removed.
- `write_dwc()` has moved to [camtrapdp](https://inbo.github.io/camtrapdp/reference/write_dwc.html). `write_eml()` is not needed for GBIF processing of Camtrap DPs and has been removed ([camtrapdp#61](https://github.com/inbo/camtrapdp/issues/61)).
- `round_coordinates()` has moved to [camtrapdp](https://inbo.github.io/camtrapdp/reference/round_coordinates.html) (#327).

### Other changes

- The first argument of many functions accepts a Camtrap DP object: not `package` anymore, but `x` (#324).
- Included dataframes `animal_pos` and `calib_models` renamed to `animal_positions` and `calibration_models`, respectively (#242).
- Column `sequenceID` in included dataframe `animal_positions` is renamed to `eventID` (#242).
- File `CITATION.cff` added to the package (#345).

- `get_record_table()` returns now 4 new columns: `longitude`, `latitude` (deployment coordinates), `clock` (clock time of the observation in radians) and `solar` (sun time of the observation in radians) (#341).

- `get_custom_effort()` returns now the effort for each deployment separately (#333). The returned data frame has two new columns: `deploymentID` and `locationName`.

# camtraptor 0.25.0

- `read_camtrap_dp()` detects Camtrap DP version from `package$profile` using 
regex (#295).
This supports reading Camtrap DPs created by the GBIF IPT.

# camtraptor 0.24.0

- Replicate old Camtrap DP 0.1.6 behaviour and populate `angle` and `radius` for 
event-based observations.
Values are taken from the first media-based observation (fields 
`individualPositionRadius` and `individualPositionAngle`) for each 
`eventID/individualID` combination (#291).
